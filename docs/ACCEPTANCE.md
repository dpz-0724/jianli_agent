# V0.9.1 Pilot 现场验收方案

## 一、验收前准备

准备三台 Windows 10/11 客户机，至少覆盖：

- 无 Python、无 Google Chrome 的干净环境；
- 已安装 Microsoft Edge 的企业办公环境；
- 存在代理、证书或安全软件的客户环境。

准备：

- 客户书面授权的智联招聘账号；
- 两个真实岗位；
- 200 条人工标注候选人黄金样本；
- 一份 V1/V2 旧数据库副本；
- 数据保存、删除和诊断包外发责任人。

## 二、安装与首次启动

1. 使用 `Package RC` 生成的发布 ZIP 或安装程序；
2. 不安装 Python，不安装 Google Chrome；
3. 启动 `招聘自动化工作台.exe`；
4. 检查工作台 Chromium 是否随包可用；
5. 检查窗口、字体、缩放、空状态和登录入口；
6. 完成智联登录、创建岗位、确认岗位标准；
7. 重启应用，确认岗位、设置和登录状态保留。

通过标准：

- 无命令行窗口；
- 无缺失 DLL；
- 无未解释安全软件拦截；
- 普通招聘人员在 10 分钟内完成登录和首个岗位；
- 所有失败均有业务提示和日志路径。

## 三、岗位标准与规则覆盖

验证：

1. JD 写“本科及以上”，结构化选择“学历不限”；
2. JD 写“至少 5 年”，结构化填写 3 年；
3. 搜索词填写 `Java Spring`，必须能力只填写 `MySQL`；
4. 必须能力和加分能力分别填写；
5. 修改已确认岗位后重新变为草稿；
6. 未确认岗位不能开始招聘。

通过标准：

- 结构化确认值是最终执行值；
- 搜索词不自动成为必须能力；
- 页面明确说明只有搜索词用于当前智联召回，其他条件用于本地评估；
- 每次确认产生可追踪版本。

## 四、受控浏览器

分别验证：

- 工作台 Chromium；
- Microsoft Edge 备用模式；
- Google Chrome 备用模式（已安装时）；
- 清除登录状态；
- 浏览器重置；
- 工作台和浏览器左右分屏；
- 候选人来源在同一登录 Profile 中打开。

故障注入：

1. 浏览器空闲时手动关闭，再点击“显示浏览器”；
2. 搜索过程中手动关闭浏览器；
3. 搜索过程中断网 60 秒后恢复；
4. 登录过期后重新登录；
5. 出现验证码或提示时执行人工接管。

通过标准：

- 失效 Context 被清理并自动重建；
- 用户能明确看到当前状态；
- 人工接管时自动化不继续点击；
- 恢复失败时生成截图、HTML、Trace 和错误码。

## 五、真实智联搜索

使用两个授权岗位分别执行：

- 5 页 / 200 人；
- 连续运行不少于 20 次；
- 正常完成、暂停继续、安全停止、登录过期、浏览器关闭等不同场景。

抽样核对：

- 姓名；
- 当前或期望职位；
- 地点；
- 学历；
- 经验；
- 活跃度；
- 平台 UID；
- 候选人来源链接。

通过标准：

- 字段准确率达到客户确认标准；
- Java 与销售等不同岗位数据、评估、阶段和导出不串；
- 页面改版或账号限制不会被错误显示成“没有候选人”；
- 失败任务均可定位原因。

## 六、逐页持久化与恢复

### 场景 A：应用强制结束

1. 启动 5 页任务；
2. 确认第 2 页显示“已安全保存”；
3. 在第 3 页处理中强制结束应用；
4. 重启并从检查点恢复。

通过标准：

- 数据库 `last_page=2`；
- 第 1、2 页候选人已经存在；
- 恢复从第 3 页开始；
- 最终候选人零丢失、同岗位零重复记录。

### 场景 B：保存失败

模拟磁盘只读、空间不足或数据库锁定。

通过标准：

- 当前页不推进检查点；
- 任务安全停止；
- 用户收到“候选人保存失败”；
- 修复后从最近已提交页恢复。

### 场景 C：安全停止

在不同页执行停止。

通过标准：已经提交的页保留，未提交页不冒充成功。

每个场景至少重复 10 次。

## 七、去重与候选人身份

准备以下样本：

- 同一 UID 重复出现；
- 第一次无 UID、第二次补充 UID；
- 同一个人职位名称发生变化；
- 同名、同岗位但实际不同的人；
- 同一候选人进入两个岗位；
- 两条误拆分记录需要人工合并。

通过标准：

- UID 命中时稳定归一；
- 同岗位不重复建档；
- 新资料生成快照；
- 跨岗位显示历史；
- 人工合并保留岗位、评估、跟进和快照；
- 合并前生成可恢复备份；
- 合并操作有操作人和审计记录。

## 八、评估准确性

黄金样本至少包括：

- 明确满足；
- 信息缺失；
- 经验区间临界；
- 明确学历或经验冲突；
- 多地点；
- 候选人资料更新后的旧评估。

通过标准：

- 缺失信息不自动淘汰；
- 经验区间不错误放行；
- 年龄、性别不影响结果；
- 每个结论能看到依据；
- 候选人资料更新后旧评估回到“信息待核验”；
- 客户确认 200 条样本结果可用于 Pilot。

## 九、数据库备份与恢复

执行不少于 20 轮：

```text
创建数据
→ 备份
→ 修改或删除数据
→ 恢复
→ 完整性检查
→ 核对岗位、候选人、评估和跟进
```

同时验证：

- 恢复前自动备份当前库；
- 损坏备份被拒绝；
- V1/V2 数据库升级到 V3；
- UID 身份索引在恢复后重建；
- 合并候选人的备份可恢复。

通过标准：20 轮全部数据一致。

## 十、导出、审计与安全

验证：

- 仅导出当前岗位；
- 导出操作人和时间；
- 岗位确认人；
- 候选人复核、阶段、跟进和合并操作人；
- 浏览器 Profile、数据库、CSV 和诊断包的本地权限；
- 诊断包脱敏后再外发；
- 卸载后的数据保留与显式清理策略。

## 十一、稳定运行

客户连续使用两周，记录：

- 每天任务数；
- 成功率；
- 页面改版或选择器异常；
- 候选人丢失或误合并；
- 浏览器恢复；
- 用户操作困惑；
- P0/P1 缺陷。

通过标准：

- 无 P0 数据错误；
- 无无法解释的候选人丢失；
- 所有失败可诊断；
- 客户确认主流程可独立完成。

## 十二、发布结论

- 自动测试通过、未现场验收：`V0.9.1 Pilot Candidate`
- 单客户全部通过并连续运行两周：`V0.9.1 Pilot`
- 至少两个客户稳定运行、完成签名与合规审查：进入 `V1.0 GA` 评审
