# V0.9 现场验收方案

## 一、安装与桌面体验

1. 在干净 Windows 10/11 客户机解压发布 ZIP；
2. 不安装 Python，不安装 Google Chrome；
3. 启动 `招聘自动化工作台.exe`；
4. 确认 PySide6 现代界面、岗位空状态和四步流程正常；
5. 创建岗位、解析岗位画像并确认标准；
6. 重启应用，确认岗位和设置保留。

通过标准：启动无命令行窗口、无缺失 DLL、无安全软件拦截，普通招聘人员可在说明内完成首个岗位。

## 二、受控浏览器

分别验证：

- 工作台 Chromium；
- Microsoft Edge 备用模式；
- Google Chrome 备用模式（客户已安装时）；
- 清除登录状态；
- 浏览器重置；
- 工作台和浏览器左右分屏；
- 候选人来源在同一登录 Profile 中打开。

通过标准：客户没有 Chrome 时仍可使用默认浏览器；浏览器状态、模式和 Profile 目录在工作台可见。

## 三、真实智联搜索

使用授权客户账号和真实岗位：

1. 首次登录；
2. 搜索 5 页、人数上限 200；
3. 连续运行不少于 10 次；
4. 验证候选人姓名、职位、地点、学历、经验和平台 UID；
5. 重复搜索不重复创建岗位候选人；
6. 新资料产生候选人快照；
7. Java 与销售两个岗位的数据、评估和导出不串。

通过标准：10 次中无未解释崩溃；失败均生成可用诊断包。

## 四、人工接管与恢复

在任务运行时验证：

- 暂停；
- 显示浏览器；
- 人工接管并操作页面；
- 继续；
- 安全停止；
- 关闭浏览器后重置；
- 从已保存页码恢复任务；
- 登录过期后重新登录并继续。

通过标准：用户始终知道当前状态，系统不在人工接管时继续点击。

## 五、岗位标准与评估

准备客户标注的黄金样本：

- 明确满足；
- 信息缺失；
- 经验区间临界；
- 明确学历或经验冲突；
- 多地点；
- 同名候选人。

通过标准：

- 未确认岗位标准不能搜索；
- 修改标准后回到草稿；
- 缺失信息不自动淘汰；
- 经验区间不错误放行；
- 年龄、性别不影响结果；
- 每个结论能看到依据。

## 六、数据与运维

验证：

- 本岗位 CSV 导出；
- 数据库备份；
- 数据库恢复；
- 诊断目录；
- 日志目录；
- 浏览器登录状态清除；
- 升级前备份和版本回滚；
- 卸载后的数据保留策略。

## 七、发布结论

- 工程测试通过但未现场验收：`V0.9 Productization Alpha`
- 单客户全部通过：`V0.9 Pilot`
- 多客户稳定运行且完成合规审查：进入 `V1.0 GA` 评审
