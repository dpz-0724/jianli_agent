# V0.9 产品决策记录

## 1. 不做真正内嵌浏览器

V0.9 采用可视化 Sidecar 浏览器，而不是 WebView/QtWebEngine 内嵌。原因：

- 保持 Playwright 完整协议；
- 登录态、Cookie 和人工操作使用同一个 Profile；
- 避免桌面 WebView 与自动化浏览器状态分裂；
- 遇到验证码和弹窗时可直接人工接管；
- 浏览器可独立重启和诊断。

## 2. 默认自带 Chromium

成熟交付不能假设客户安装 Google Chrome。正式发布目录必须包含固定 Playwright 版本匹配的 Chromium。

Edge 和 Chrome 为备用 channel；其他浏览器在 V0.9 不支持。

## 3. 岗位画像必须确认

系统解析 JD 只能生成草稿。搜索与评估属于高影响业务动作，必须由招聘人员确认岗位标准。修改任何岗位要求后，确认状态失效。

## 4. 自动化必须可接管

用户必须能看到任务状态，并可执行暂停、显示浏览器、人工接管、继续、安全停止和恢复。系统不得把验证码或未知页面当成“无候选人”。

## 5. 不以大模型替代确定性流程

V0.9 优先保证岗位隔离、证据、审计和恢复。模型能力可以用于岗位画像建议和候选人摘要，但不得绕过确定性校验和人工确认。

## 6. 产品状态保持 Alpha

代码和 CI 通过不等于客户环境可交付。没有完成真实智联账号连续运行、安装签名、升级回滚和合规审查前，不标记为正式 V1。
