# 招聘自动化工作台 Pilot 运行手册

## 1. Pilot 目标

Pilot 不是验证“界面能打开”，而是验证以下五件事：

1. 招聘人员能独立完成登录、建岗、确认标准和开始招聘；
2. 真实智联页面能稳定采集候选人；
3. 浏览器或应用异常时，已提交候选人不丢失；
4. 去重、评估和人工处理状态可信；
5. 数据能够备份、恢复、审计和安全交接。

## 2. 使用边界

当前 Pilot 只支持：

- 单个客户；
- 单个 Windows 用户；
- 单台受控电脑；
- 客户本人授权的智联招聘账号；
- 人工确认岗位标准和候选人决定。

不支持：

- 多人同时操作同一个数据库；
- SaaS 多租户；
- 自动淘汰或自动录用；
- 无人监管的大规模批量账号操作；
- 360、搜狗、QQ 浏览器、Firefox 或 WebKit。

## 4. 首次启动

1. 解压 RC ZIP 或运行安装程序；
2. 启动工作台；
3. 点击“打开智联并登录”；
4. 在受控浏览器中完成登录；
5. 返回工作台点击重新验证；
6. 创建第一个岗位；
7. 填写结构化条件和 JD；
8. 确认岗位标准；
9. 先执行 1 页、20 人的小任务。

第一轮不要直接执行 20 页或 2000 人。

## 5. 岗位标准确认原则

招聘人员必须确认：

- 搜索关键词只用于平台召回；
- 学历、经验、地点和能力条件用于本地评估；
- “不限”是否确实代表不设硬性条件；
- 必须能力是否真的属于必须条件；
- 加分能力是否不应导致自动冲突；
- 修改岗位标准后是否需要重新评估既有候选人。

## 6. 每日运行流程

### 开始前

- 确认智联登录有效；
- 选择正确岗位；
- 检查岗位标准已确认；
- 先备份数据库；
- 检查昨日未完成任务。

### 运行中

- 观察当前页和累计安全保存人数；
- 遇到验证码、提示或特殊页面时先暂停并人工接管；
- 不要同时手工操作正在自动运行的页面；
- 不要直接结束进程，除非正在执行故障注入测试。

### 运行后

- 核对本次发现数与新入池数；
- 抽样检查字段；
- 查看重复和跨岗位标记；
- 处理待复核候选人；
- 记录异常和诊断目录。

## 7. 故障处理

### 浏览器被关闭

1. 点击“显示浏览器”；
2. 系统应自动重建浏览器；
3. 如未恢复，点击“重置浏览器”；
4. 从任务页恢复最近已提交页；
5. 仍失败时导出诊断目录。

### 网络中断

1. 暂停任务；
2. 恢复网络；
3. 人工确认当前页面；
4. 点击继续；
5. 如任务失败，从最近已提交页恢复。

### 候选人保存失败

1. 不要继续任务；
2. 检查磁盘空间、文件权限和数据库占用；
3. 先备份当前数据库；
4. 修复后从最近已提交页恢复；
5. 核对前面页候选人是否存在。

### 候选人疑似重复

1. 查看平台 UID、来源、职位、地点、学历和经验；
2. 确认是同一个人后选择两行；
3. 当前行作为保留记录；
4. 点击“合并所选重复候选人”；
5. 系统会在合并前自动备份数据库；
6. 合并后核对岗位、阶段、跟进和快照。

### 候选人疑似误合并

当前版本没有一键拆分。立即停止继续处理，使用合并前自动备份恢复数据库，并将样本交给技术团队分析。

每个失败必须记录：

- 任务 ID；
- 时间；
- 当前页；
- 错误提示；
- 是否生成诊断包；
- 是否恢复成功；
- 是否发生候选人丢失或重复。

## 9. 数据管理

每天结束前：

1. 创建数据库备份；
2. 将备份放到客户批准的位置；
3. 不通过公共聊天工具发送原始数据库；
4. CSV 使用后按制度删除；
5. 诊断包外发前检查截图和 HTML 是否包含候选人信息；
6. 不共享浏览器 Profile。

## 10. Pilot 退出条件

任何一项发生时暂停 Pilot：

- 候选人数据丢失；
- 同岗位重复记录无法解释；
- 大量候选人误合并；
- 恢复后数据不一致；
- 账号异常或平台明确限制；
- 未经授权的数据导出；
- 安全软件持续拦截；
- 无法生成诊断信息的崩溃。

## 11. Pilot 完成标准

- 连续运行两周；
- 至少两个真实岗位；
- 至少 20 次真实搜索；
- 故障恢复测试全部完成；
- 200 条黄金样本完成核对；
- 备份恢复完成 20 轮；
- 无 P0 数据问题；
- 招聘人员可独立完成主流程；
- 客户、技术和数据责任人共同签字确认。
