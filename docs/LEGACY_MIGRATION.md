# 从旧版原型迁移到 V1

## 入口变化

旧版：

```bash
python app.py
```

新版：

```bash
python workbench_app.py
```

旧 `app.py` 和旧 `code/db.py` 不再作为生产主链路。

## 数据变化

旧版将所有候选人放在一个全局池中；新版必须先创建岗位，再将候选人关联到岗位。

旧数据库不会自动迁移到新数据库，避免把已污染的跨岗位评分直接继承。需要保留的数据建议：

1. 从旧版导出 CSV；
2. 对姓名、来源和隐私字段进行人工检查；
3. 后续通过受控导入工具导入指定岗位。

## 评估变化

旧版单一 100 分模型停止作为生产依据。新版使用：

- `PASS`：未发现明确冲突且必要信息足够；
- `REVIEW`：信息缺失或区间不确定；
- `CONFLICT`：存在明确证据低于确认的硬性要求。

分数只用于同一岗位内部排序，不跨岗位比较。
